# 문제 해결 기록 (Day 1~4)

개발 중 만난 오류와 품질 문제를 원인과 해결 방법, 확인 결과와 함께 날짜별로 정리했다.
리포트의 "문서 처리", "한계", "실패 분석" 항목의 근거로 쓴다.
Day 5 개선 실험은 [evaluation.md 2부](evaluation.md)에 따로 정리했다.

- **분류**: 환경(개발 환경·도구) · 수집 · 정제 · 중복 · 청킹 · 인덱싱 · 평가 · RAG · UI
- **교훈**: 같은 문제를 다시 만나지 않기 위해 기억할 점

## Day 1 — 수집

| # | 분류 | 문제 | 원인 | 해결 | 확인 |
|---|---|---|---|---|---|
| 1 | 수집 | 제공 데이터 파일명 매칭 실패 | macOS 는 한글 파일명을 자모 분리형(NFD)으로 저장, 코드의 문자열은 완성형(NFC) | `unicodedata.normalize("NFC")` 로 맞춘 뒤 비교 (`collector/load_provided.py`) | 전 파일 매칭 |
| 2 | 환경 | SQLite `disk I/O error` | 작업 세션에 파일 삭제 권한이 없어 SQLite 가 임시 저널 파일을 지우지 못함 | 세션마다 폴더 삭제 권한을 받아 해결. 남은 저널은 SQLite 가 다음 연결 때 스스로 되돌림 | `PRAGMA integrity_check` 통과 |
| 3 | 수집 | DART 사업보고서 15건 중 7건 본문 추출 실패 | 공시 zip 안에 첨부 xml 이 여러 개인데, 본문이 아닌 첨부 파일을 먼저 읽음 | 본문 파일 `{접수번호}.xml` 을 우선 선택하고, 없으면 가장 큰 파일 사용 (`collector/crawl_dart.py`) | 33건 모두 추출 |
| 4 | 수집 | 산업부·과기정통부 보도자료의 본문이 거의 비어 있음 | 본문이 웹페이지가 아니라 첨부파일(PDF·HWPX)에만 있음. 과기정통부는 PDF 없이 HWPX 만 제공 | 첨부파일을 내려받아 PDF 는 PyMuPDF, HWPX 는 zip 안 XML 의 텍스트 태그로 추출 (`crawl_korea_kr.py`) | 보도자료 438건 본문 확보 |
| 5 | 수집 | 저장된 "PDF" 2건을 열 수 없음 | 서버가 오류 페이지(HTML)를 PDF 이름으로 내려줌 | 파일 앞부분이 `%PDF` 인지 확인하는 `is_pdf()` 추가, 아니면 건너뛰고 기록 | 오류 파일 제외 |
| 6 | 수집 | PDF 처리 중 MuPDF 경고가 대량 출력 | 일부 PDF 의 사소한 형식 오류 | 경고 출력 끔 (추출 결과에는 영향 없음) | 로그 정리 |
| 7 | 수집 | KIET 보고서의 쪽 수가 실제와 다름 | 쪽 구분 문자 `\f` 가 쪽 본문 안에도 들어 있어, `\f` 로 다시 나눌 때 쪽이 더 잘게 쪼개짐 | 쪽마다 본문 속 `\f` 를 먼저 지운 뒤 `\f` 로 이어 붙임 (`load_kiet.py`) | 쪽 수 일치 |
| 8 | 수집 | KIET 사이트에서 자동 다운로드 불가 | robots.txt 가 파일 경로 수집을 금지 | 크롤링하지 않고 수동 다운로드 후 목록(manifest)으로 적재 | 7편 적재, 출처 URL 기록 |
| 9 | 수집 | 작업 세션에서 DART·정책브리핑 접속 불가 | 작업 환경의 네트워크 제한 | 수집 스크립트를 맥(로컬)에서 실행 | 수집 로그(`collect_log`) 기록 |

### 개발 환경

| # | 문제 | 원인 | 해결 |

## Day 2 — 정제 · 중복 처리 · 청킹 · 임베딩 결정

| # | 분류 | 문제 | 원인 | 해결 | 확인 |
|---|---|---|---|---|---|
| 15 | 정제 | KIET 보고서 1편(paper_806)의 89쪽 중 82쪽이 깨진 글자 | PDF 의 글꼴 정보 문제로 텍스트 추출 불가 | 제어문자 비율 5% 이상이면 `garbled` 로 표시하는 검사 추가, 해당 보고서 제외(승인) | 정제 제외 10건 = 빈 뉴스 9 + 깨진 보고서 1 |
| 16 | 정제 | DART 본문에 `&cr;` 와 이미지 파일명 줄이 섞임 | DART XML 의 줄바꿈 표기와 이미지 참조 | `&cr;` → 줄바꿈, 이미지 줄 삭제 (`indexer/parse.py`) | 청크 샘플에서 사라짐 |
| 17 | 정제 | 보도자료·보고서 청크에 목차 줄, 머리말, 쪽 번호가 들어감 | PDF 의 반복 머리말과 목차가 본문처럼 추출됨 | 문서 종류별 규칙: 목차 줄 삭제, 반복 머리말 패턴 감지, 쪽 번호·담당자 연락처 삭제 | 청크 샘플 재확인 |
| 18 | 중복 | 중복 탐색 중 메모리 부족으로 중단 | 4.7만 건의 문자 조각(shingle) 집합을 모두 메모리에 보관 (작업 환경 3GB) | 문서마다 MinHash 서명(128개 숫자)만 남기고 조각 집합은 버림 | 전체 실행 완료 |
| 19 | 중복 | 완전 중복인데 "유사 중복"으로 기록됨 | 쌍의 한쪽에만 사유를 기록 | 쌍의 양쪽 모두에 사유 기록 (`indexer/dedup.py`) | 사유별 건수 재확인 |
| 20 | 중복 | 유사도 기준값(0.8 vs 0.6) 결정 근거 부족 | — | 0.8 로 처리하고 Day 3 검색 결과의 쏠림(상위 5개 중 유사 쌍)을 측정해 판단하기로 함 → 6쌍뿐이라 0.8 유지 | `report/design.md 2부`, `evaluation.md 1부` 2절 |
| 21 | 청킹 | 제목만 있는 짧은 청크가 생김 | 구조 기반 분할(설정 B)이 제목 줄을 독립 단위로 자름 | 짧은 제목 단위는 다음 내용과 합치는 `pack()` 추가 (`indexer/chunk.py`) | 빈약한 청크 제거 |
| 22 | 청킹 | 청크 조회 쿼리가 매우 느림 | `LIKE` 검색과 문서별 반복 조회, 인덱스 없음 | `chunks(doc_id)` 인덱스 추가, 한 번에 읽어 흘려보내는(스트리밍) 방식으로 변경 | 조회 시간 단축 |
| 23 | 인덱싱 | 무료 임베딩 모델(KURE-v1) 시험 중 노트북 과열 | 로컬 CPU/GPU 로 대량 임베딩 | 같은 샘플로 두 모델을 비교(파일럿): Hit@3 동점, 전체 인덱싱 예상 35분 vs 5시간 30분 → OpenAI `text-embedding-3-small` 선택 | `report/design.md 1부` |

**교훈**: 정제 규칙은 청크 샘플을 직접 보고 만든다. 기준값은 감으로 정하지 않고 측정해서 정한다.

## Day 3 — 인덱싱 · 검색 · 1차 측정

| # | 분류 | 문제 | 원인 | 해결 | 확인 |
|---|---|---|---|---|---|
| 24 | 인덱싱 | 임베딩 생성이 1시간 가까이 걸려 중간 실패가 걱정됨 | 청크 9~10만 개 | 100개 단위 호출, 실패 시 재시도(대기 시간 증가), 이미 저장된 id 는 건너뛰는 이어서 실행, 끝난 뒤 개수 검증 (`indexer/embed.py`) | A 105,986개, B 92,237개 일치, 빈 문서 0 |

| 26 | 평가 | 같은 질문을 평가할 때마다 임베딩 비용 발생 | 질문 임베딩을 매번 새로 만듦 | 질문 임베딩을 `data/cache/query_embeddings.json` 에 저장해 재사용 | 재채점은 API 호출 0 |
| 27 | 평가 | 1차 측정 Hit@3 0.588 로 낮게 나옴 | ① 1차 자료가 뉴스에 묻힘 ② 정답 라벨이 1차 자료로만 되어 있어, 질문에 맞게 답하는 뉴스도 오답으로 집계 ③ 시점 질문 취약 | ②는 후보 뉴스 본문을 직접 읽고 확인한 29건을 정답에 추가(gold_v2). ①은 Day 5 실험 대상으로 남김 | B Hit@3 0.588 → 0.794 (검색 개선이 아니라 측정 보정) |
| 28 | 평가 | 보도일을 사건 날짜로 오인할 위험 | 기사가 나온 날과 사건(출범·통과 등)이 일어난 날은 다를 수 있음 (사용자 지적) | 정확한 시점을 묻는 질문은 본문에 날짜가 있는 문서만 정답으로 인정 → e11 은 보강하지 않음 | `evaluation.md 1부` 5절 |
| 29 | 평가 | 보고서 표의 메모 행을 실수로 덮어씀 | 문서 일부를 고치는 중 표 행 범위를 잘못 지정 | 이전 내용으로 복원 | `questions.md 2부` 확인 |
| 30 | 환경 | SQLite `disk I/O error` 재발 | 새 세션에서 삭제 권한이 초기화됨 (#2 와 같은 원인) | 권한 재요청 | 정상 동작 |

**교훈**: 평가 수치가 낮으면 검색보다 먼저 평가셋(정답 라벨)이 맞는지 확인한다. 측정 보정과 실제 개선은 구분해서 기록한다.

## Day 4 — RAG 체인 · 챗봇 UI

| # | 분류 | 문제 | 원인 | 해결 | 확인 |
|---|---|---|---|---|---|
| 31 | 환경 | 작업 환경에서 OpenAI 호출 불가 (프록시 403) | 작업 세션의 네트워크 제한 | 저장된 질문 임베딩과 가짜 LLM(정해진 문장을 돌려주는 테스트용 모델)으로 체인·화면을 시험하고, 실제 모델 확인은 맥에서 실행 | Streamlit AppTest 로 화면 흐름 검증 |
| 32 | RAG | 답할 수 있는데 "제공된 자료에서 확인할 수 없습니다"로 시작한 뒤 답을 이어 씀 | 프롬프트 규칙 2가 "거절하면서 관련 사실을 덧붙여도 된다"고 허용해 애매한 질문에서 거절 문구를 먼저 씀 | 판단 순서를 명시: 일부라도 답할 수 있으면 거절 문구 없이 답하고 빠진 부분만 "※ 문서에서 확인되지 않는 부분"으로 표시. 이유·배경 질문은 답할 수 있는 경우로 명시 | 같은 질문에서 거절 문구 없이 답변 |
| 33 | RAG | 거절 문구를 모델이 조금 바꿔 씀 ("…에 대한 정보는 확인할 수 없습니다") | 문장을 그대로 쓰라는 지시가 약함 | 프롬프트에 틀린 예 추가 + 거절 판정 함수 `is_refusal()` 이 변형도 인정 (첫 문장에 "제공된 자료"·"확인할 수 없" 포함) | 판정 테스트 4건 통과 |
| 34 | RAG | 거절 뒤 "참고로" 문장에 출처 없는 일반 설명이 붙음 | 덧붙임 조건이 느슨함 | 출처 번호를 댈 수 있는 사실만 덧붙이도록 규칙 강화 | — |
| 35 | UI | 프롬프트를 고쳤는데 답변이 그대로 | ① `st.cache_resource` 가 처음 만든 체인(옛 프롬프트)을 계속 사용 ② 화면에 보인 것은 저장된 옛 대화 | 프롬프트를 바꾸면 앱을 껐다 켜고 "대화 새로 시작" | 새 답변 확인 |
| 36 | UI | 출처 라벨에 "언론 보도"가 두 번, 출처 순서가 [2][4][1] | 종류 라벨과 별도 태그를 함께 표시, 인용 순서대로 정렬 | 1차 자료만 "1차 자료" 표시, 인용 출처는 번호 순 정렬 | 화면 확인 |
| 37 | UI | 첫 질문 뒤에도 예시 질문 버튼이 남음 | 버튼은 질문 처리 전에 그려짐 | 버튼 영역을 `st.empty()` 로 만들고 질문이 들어오면 비움 | AppTest 확인 |
| 38 | UI | 후속 질문("그럼 삼성전자는?")에 답변이 나오지 않음 | 답변 생성 도중 화면이 다시 실행되면(코드 변경·위젯 조작) 그 실행이 중단되고, 질문만 기록에 남음 | 기록의 마지막이 답 없는 질문이면 다음 실행에서 이어서 답하도록 처리 | 서버 기록상 재작성·검색은 완료돼 있었음. AppTest 로 이어 답하기 확인 |
| 39 | UI | 답변 중 사이드바를 건드리면 답변이 끊김 | 위젯을 조작하면 화면 전체가 처음부터 다시 실행됨 | 사이드바를 `st.fragment` 로 분리. 프래그먼트 실행은 진행 중인 답변을 끊지 않고 끝난 뒤로 미뤄짐(Streamlit 1.65 소스 확인). 검색 조건은 다음 질문부터 적용 | AppTest: 필터 적용·점수 표시·대화 초기화 정상 |
| 40 | 환경 | 프로젝트에 `.agents/`, `.claude/` 폴더가 생김 | Streamlit 실행 시 AI 코딩 도구용 안내 문서 링크를 자동 생성 | 프로젝트와 무관 → `.gitignore` 에 추가 | `git status` 에서 제외 |
| 41 | 환경 | 커밋 메시지에 이미 첫 커밋에 들어간 변경(gold_v2)을 적음 | 커밋 범위 확인 전에 메시지 작성 | push 전이라 메시지만 수정(amend) | 커밋 파일 목록과 메시지 일치 |

**교훈**: 화면은 "다시 실행될 수 있다"는 전제로 만든다. 질문·답변 기록은 중단되어도 이어갈 수 있어야 한다. 프롬프트 규칙은 판단 순서와 예시로 쓴다.
