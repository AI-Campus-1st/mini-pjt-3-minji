# 청킹 설계 — 설정 A(고정 길이) vs 설정 B(문서 구조 기반)

> 작성일: 2026-11-04 (Day 2) · 리포트 4항 "청킹 전략"의 근거 자료
> 코드: `indexer/chunk.py` · 결과: `store/docs.db` → `chunks` (config = A / B), 실행 기록 `collect_log` (step='chunk')
> 비교 측정(Hit@3)은 Day 3 에 진행

## 1. 비교 설계

**크기는 같게(목표 1,000자), 나누는 방법만 다르게** 두 설정을 만들었다.
결과 차이를 "나누는 방법" 하나로 설명하기 위함이다 (가이드 4-9: 한 번에 하나의 변수만 변경).
청크 크기 비교(500자 vs 1,000자)는 이긴 방법으로 Day 5에 여유가 있으면 추가한다.

| 설정 | 나누는 방법 | 청크 앞머리 |
|---|---|---|
| A 고정 길이 (기준선) | 모든 문서를 1,000자씩, 겹침 100자 | 문서 제목 |
| B 문서 구조 기반 | 문서 종류별 자연 경계에서 목표 1,000자로 묶음 | 문서 제목 + 소제목(DART) / 쪽 번호(KIET) |

### 설정 B 의 문서 종류별 규칙 (가이드 4-4 청킹 방향 반영)

| 문서 | 데이터 특성 | 나누는 방법 |
|---|---|---|
| 뉴스 | 줄바꿈 없는 한 덩어리, 중앙값 1,322자, 43%가 1,200자 이하 | 1,200자 이하는 **기사 통째로**, 길면 **문장 경계**로 묶음 (앞 청크 마지막 문장을 겹침으로 반복) |
| 보도자료 | □ ○ ㅇ 개조식, 중앙값 4,142자 | **개조식 항목 경계**로 묶음 |
| DART | `## 1. 사업의 개요` 같은 소제목, 중앙값 2.8만 자 | **소제목 단위** → 길면 줄 경계로 묶음, 청크에 **소제목 표시** |
| KIET | 쪽 구분, 중앙값 4만 자 | **쪽 → 문단 경계**로 묶음, 청크에 **시작 쪽 번호 표시** |

공통: 짧은 소제목 줄은 다음 문단과 함께 묶고, 너무 짧은 마지막 조각은 앞 청크에 붙인다.

## 2. 결과

| 항목 | 설정 A | 설정 B |
|---|---|---|
| 청크 수 | 105,986 | **92,237** |
| 뉴스 / 보도자료 / DART / KIET | 99,827 / 4,678 / 1,088 / 393 | 86,235 / 4,489 / 1,091 / 422 |
| 본문 길이 5% / 50% / 95% | 98 / 1,000 / 1,000자 | **370 / 940 / 1,110자** |
| 최소 / 최대 | 1 / 1,000자 | 29 / 1,547자 |
| 200자 미만 청크 | **10,638개 (10%)** | 374개 (0.4%) |
| 1,400자 초과 청크 | 0 | 12 (짧은 소제목이 붙은 경우) |

- 설정 A 의 짧은 청크 10%는 고정 창의 **마지막 자투리**다 (예: 1,050자 기사 → 1,000자 + 150자).
- 설정 B 의 200자 미만 청크는 대부분 **원래 짧은 기사**(사진 설명 기사, 속보 한 줄)다.
- 임베딩 입력 한도(OpenAI 8,191토큰) 대비 최대 1,547자로 충분히 짧다.

## 4. 청킹 과정에서 발견해 고친 것 (정제 단계로 되돌아가 수정)

| 발견 | 원인 | 조치 |
|---|---|---|
| DART 청크에 `&cr;` 문자열 | DART 원문 XML 의 줄바꿈 표기가 글자로 남음 (5건) | `parse.py`: `&cr;` → 줄바꿈 |
| KIET 청크가 목차("…지원 현황·······37")로만 채워짐 | 목차 쪽이 그대로 청킹됨 (KIET 3편, 보도자료 19건) | `parse.py`: 점선 + 쪽 번호 줄 제거 |
| 설정 B 에 소제목 한 줄짜리 청크 ("4) 시장여건 및 경쟁상황") | 소제목 뒤 문단이 길면 소제목만 먼저 잘림 | `chunk.py`: 짧은 앞부분은 다음 단위와 함께 묶음 |
| 뉴스 끝 "Copyright 매일경제." | 끝부분 안내문 목록에 없던 표기 | `parse.py`: 끝부분 안내문 목록에 추가 (빈 기사 1건 추가 제외) |

→ 수정 후 정제·중복 처리·청킹을 다시 실행. 중복 처리 후 뉴스 44,839건 (Copyright 문구만 있던 기사 1건, 그와 묶였던 1건 반영).
