## 개요

AI 반도체 산업 동향·기업 전략 분석 RAG 챗봇을 6일 안에 만들고, 답변을 신뢰할 수 있는 근거를 수치로 제시한다.
**평가는 마지막 단계가 아니라 Day 3부터 반복하는 작업이다.**

- **대상 사용자**: 반도체·IT 기업 전략기획/산업분석 주니어 담당자
- **업무 상황**: 뉴스·기업 공시·정부 정책·산업 보고서를 교차 확인하는 리서치

| 문서 종류 | 건수 | 성격 | 수집 방식 |
|---|---|---|---|
| news | 47,428 | 언론 보도 (중복 제거 전) | 제공 데이터 |
| dart | 33 | 기업 공시 (7개사 사업보고서) | DART API |
| press | 438 | 정부 정책 원문 (산업부·과기정통부·기재부) | 정책브리핑 크롤링 |
| report | 7 | 산업 분석 (KIET) | 수동 다운로드 |

```
Day 1 탐색·수집 → Day 2 정제·평가셋 → Day 3 인덱싱·1차 측정
→ Day 4 RAG·UI → Day 5 평가·개선 → Day 6 정리·리포트
```

## 리포트 근거와 위험 대응

수집 단계별 건수는 `store/docs.db`의 `collect_log` 테이블에 자동 기록된다.

| 리포트 항목 | 확보한 근거 |
|---|---|
| 2. 지식베이스 구성 | EDA 결과, 관련성 필터 근거 (본문에 'AI 반도체' 0회인 문서 50%) |
| 2. 접근 제약 대응 | DART·정책브리핑: 세션 네트워크 차단 → 로컬 실행 / KIET: robots.txt가 파일 경로 금지 → 수동 다운로드 / 과기정통부: PDF 없음 → HWPX 추출 |
| 4. 문서 처리 | 수집 단계별 건수 (예: 보도자료 1,447 → 603 → 438) |

| 이런 상황이면 | 대응 |
|---|---|
| Day 2 중복 처리가 길어짐 | 정상. 가이드도 Day 2의 주요 작업으로 봄 |
| Day 3 임베딩이 너무 오래 걸림 | 뉴스 기간 축소, 배치 크기 조정 |
| 검색 결과가 질문과 무관함 | 청크에 문서 제목이 들어갔는지 먼저 확인 |
| 답변이 엉뚱함 | 모델을 바꾸기 전에 검색 결과부터 확인 |
| 근거 없는 답변이 나옴 | 거절 지시 강화, 유사도 임계값 적용 |
| 일정이 밀림 | 심화 확장을 빼고 평가·개선 완료를 우선 |
