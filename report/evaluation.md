## 1부. 1차 측정 (baseline) — 청킹 설정 A vs B

> 측정일: 2026-11-05 (Day 3) · 결과: `eval/results/retrieval_baseline_A.json`, `retrieval_baseline_B.json`
> 조건: 임베딩 text-embedding-3-small, 중복 처리 0.8, 문서 단위 상위 10개(청크 50개에서 문서별 최고 점수), 평가셋 40문항(답변 가능 34)

### 1. 결과

| 지표 | A 고정 길이 | **B 구조 기반** |
|---|---|---|
| Hit@1 | **0.324** | 0.265 |
| **Hit@3** | 0.471 | **0.588** |
| Hit@5 | 0.559 | **0.647** |
| MRR@10 | 0.420 | **0.429** |
| Hit@3 사실 (15) | 0.667 | **0.800** |
| Hit@3 비교 (7) | 0.286 | **0.571** |
| Hit@3 시점 (6) | 0.167 | 0.167 |
| Hit@3 종합 (6) | 0.500 | 0.500 |

→ **설정 B 채택** (Hit@3 +11.7%p, 비교 유형 2배). A 는 Hit@1 만 근소 우위.
→ Day 3 종료 기준 충족: **현재 Hit@3 = 0.588 (설정 B)**

### 2. 상위 5개 쏠림 → 중복 처리 기준 0.8 유지

| | A | B |
|---|---|---|
| 상위 5개 안 유사도 ≥ 0.6 문서 쌍 | 5쌍 / 5문항 | 6쌍 / 6문항 |

- B 의 6쌍 중 3쌍은 **같은 기업의 다른 연도 사업보고서**(유사도 0.77~0.8)로, 중복이 아니라 시점 비교에 필요한 문서다.
- 뉴스 재배포본 쌍은 3쌍(40문항 중)뿐 → **검색 상위가 같은 내용으로 몰리는 현상은 거의 없다.**
- 결론: 중복 처리 기준을 0.6으로 낮출 근거가 없어 **0.8 유지** (report/design.md 2부 5장의 판단 절차에 따름).

### 3. 실패 분석 (설정 B, 5위 밖 12문항)

#### 원인 ① 1차 자료가 뉴스에 묻힘 (검색 계층)

| 문서 종류 | 청크 비중 | 상위 5개 결과 비중 (40문항 × 5) |
|---|---|---|
| news | 93.5% | 72.5% (145) |
| dart | 1.2% | 14.5% (29) |
| press | 4.9% | 8.0% (16) |
| report | 0.5% | 5.0% (10) |

- 상위 5개가 **전부 뉴스**인 문항이 14개. 이 중 질문이 **사업보고서를 직접 지목**한 e16("2025년 사업보고서에서…")도 뉴스만 검색됨.
- 1차 자료 비중이 작아(청크의 6.5%) 비슷한 주제의 뉴스 수만 건과 경쟁하면 밀린다.
- 개선 후보 (Day 5): 질문에 출처가 드러나면 문서 종류 필터 적용, 또는 **문서 종류별 균형 검색**(뉴스·1차 자료를 나눠 가져와 합침).

#### 원인 ② 정답 라벨이 1차 자료에 한정됨 (평가 설계)

- 예: e11 "PIM 사업단은 언제 출범했나?" → 1위 뉴스 "7년간 4천억원 투자…범부처 PIM인공지능반도체 사업단 출범"은 **질문에 답하는 문서**지만 정답 목록(보도자료)에 없어 실패로 집계됨.
- e25(정부 NPU 지원 정책), e32(온디바이스 사업) 등도 상위 뉴스가 관련 내용을 담고 있음.
- → Hit 수치가 **실제 검색 품질보다 낮게** 나왔을 가능성. 정답 라벨 보완 여부 결정 필요.

#### 원인 ③ 시점 질문 취약 (Hit@3 0.167)

- "2022년 이후 어떻게 전개됐나", "2023~2024년 변화" 같은 질문은 여러 시기 문서가 필요한데, 의미 검색은 **최근 기사 위주**로 비슷한 내용만 가져온다.
- 개선 후보: 연도 필터·기간별 분할 검색 (Day 5).

### 4. 거절 임계값에 대한 관찰 (Day 4 반영)

| 1위 유사도 | A | B |

| 답변 가능 평균 / 최소 | 0.662 / 0.540 | 0.660 / 0.549 |
| 답변 불가 평균 / 최대 | 0.564 / 0.741 | 0.559 / 0.739 |

### 5. 정답 라벨 보완 후 재측정 (gold_v2)

원인 ②에 대응해, 질문에 실제로 답하는 뉴스를 **본문을 직접 읽고 확인한 뒤** 정답에 추가했다. 중복 처리 기준은 0.8을 유지했다.

- 원본 라벨은 `eval/eval_set_v1.jsonl`, `eval/eval_candidates_v1.json`에 백업했다.
- 결과 파일은 `eval/results/retrieval_gold_v2_{A,B}.json`이다.
- 질문 임베딩은 캐시를 재사용했으므로 baseline과 질문 벡터가 같고, OpenAI 재호출은 없었다.

#### 판정 원칙

- 정답 문서는 대표 문서(keep=1)만 인정한다.
- **정확한 시점을 묻는 질문**은 본문에 날짜가 명시돼야 한다. 보도일은 사건일과 다를 수 있으므로 보도일로 추정하지 않는다.
- **흐름·연도 질문**은 보도일로 연도가 확정되는 상대 표현("지난해", "올해")을 인정한다.
- 출처를 지정한 질문(e16, e20, e26)은 보완하지 않는다.

#### 추가 내역 (8문항, 29건)

| 문항 | 추가 | 비고 |
|---|---|---|
| e23 | 1 | 2024 실적·HBM 비중 (2023 수치 없음, 부분 정답) |
| e24 | 5 | 반도체특별법 논의 경과 |
| e25 | 6 | 정부 NPU·국산 AI반도체 지원 |
| e27 | 3 | HBM4 개발·경쟁 |
| e28 | 1 | AI반도체 대학원 3개교·90명 |
| e30 | 4 | 국산 AI반도체 상용화·기술지원센터 |
| e32 | 4 | 온디바이스 AI칩 지원·K-온디바이스 사업 |
| e34 | 5 | 반도체 수출 규모·구성 변화 |

**제외한 후보 문서**는 다음과 같다.

- e11의 뉴스 전체: 본문에 출범 연월이 없고 보도일만 있다.
- 사설, 수치가 없는 기사, 주제가 대부분 무관한 기사는 모두 제외했다.
  - 예: e30 news_20230817_073331은 UAM·바이오가 중심이다.

#### 결과 비교

| 지표 | A (baseline → v2) | B (baseline → v2) |
|---|---|---|
| Hit@1 | 0.324 → 0.500 | 0.265 → 0.412 |
| Hit@3 | 0.471 → 0.706 | 0.588 → 0.794 |
| Hit@5 | 0.559 → 0.794 | 0.647 → 0.824 |
| MRR@10 | 0.420 → 0.611 | 0.429 → 0.586 |
| Hit@3 time | 0.167 → 1.000 | 0.167 → 0.833 |
| Hit@3 synthesis | 0.500 → 1.000 | 0.500 → 1.000 |

#### 해석

- **검색 성능이 좋아진 것이 아니다.** 검색 결과는 같고 **측정을 바로잡은** 것이다.
  - 기존 수치는 실제보다 낮게 나와 있었다.
- 시점 질문이 0.167에서 0.833으로 오른 것도 라벨 효과다. 따라서 원인 ③(시점 질문 취약)은 원래 판단보다 약하다.
  - 단, e23(B 설정에서 10위 밖)은 실제로 검색에 실패했다.
- B 설정에서 5위 밖에 남은 문항은 **6개**다. 이것이 Day 5 개선 실험의 대상이다.
  - e07, e11, e18, e19, e23은 검색 실패다. 대부분 1차 자료가 뉴스에 묻힌 경우(원인 ①)다.
  - e16은 출처를 지정한 질문이다.
- 설정 B는 Hit@3·Hit@5에서 앞서고, A는 Hit@1·MRR에서 앞선다. 최종 설정은 Day 5 개선 실험 후 확정한다.

## 2부. 답변 평가 및 개선 실험 (Day 5)

평가셋 40문항(답변 가능 34 · 답변 불가 6)을 챗봇과 같은 RAG 체인(`rag/chain.py`)으로 답하고 채점했다.

- 실행: `python eval/run_answers.py --tag <태그>` → `eval/results/answers_<태그>.jsonl`
- 채점: `eval/grades_<태그>.json` (문항별 정확/부분/오답, 출처 판정, 실패 원인 계층, 판정 이유)
- 공통 조건: gpt-4o-mini, temperature 0, 청킹 설정 B, 문서 6건, 질의 재작성 끔(단일 질문)

### 1. 채점 기준

| 항목 | 기준 |
|---|---|
| 정확 | 정답 요지의 핵심 요소를 문서 근거로 모두 제시 |
| 부분 정확 | 핵심 일부만 맞거나, 일부를 "확인할 수 없음"으로 남김 |
| 오답 | 수치·결론이 틀림, 또는 답할 수 있는데 거절(과잉 거절) |
| 출처 정확성 | 인용한 [n] 문서가 실제로 그 문장의 근거인가 (정확/부분/오류/없음) |
| 거절 정확도 | 답변 불가 문항에서 거절한 비율 |

### 3. 실험 1 — 문서당 청크 1개 → 3개 (`chunks3`)

**가설**: 긴 문서(보도자료 최대 37청크, DART 최대 51청크)는 1위 청크에 답이 없을 수 있다. 상위 50개 청크 안의 같은 문서 청크를 최대 3개까지 넘기면 해결된다.

**사전 측정 (API 호출 없이)**: 정답 수치가 모델에 넘어가는지

| 문항 | 1청크 | 3청크 |
|---|---|---|
| e09 | 없음 | 751.5 포함 |
| e22 | 없음 | 14.0%, 603.3 포함 |
| e14, e26, e33 | 없음 | 없음 (답 청크가 상위 50위 밖 — 예: e26 특허 표 51위) |

**결과**

| 지표 | baseline | chunks3 |
|---|---|---|
| 정확 / 부분 / 오답 | 17 / 8 / 9 | **19 / 7 / 8** |
| 거절 정확도 | 6/6 | 6/6 |
| 과잉 거절 | 4 | 5 (e01 추가) |
| 정답 문서 인용률 | 0.529 | **0.647** |
| 출처 정확성 (정확) | 24 | 26 |
| 평균 응답 시간 | 2.85초 | 3.01초 |
| 평균 컨텍스트 길이 | 5,599자 | 8,797자 |

- 개선: e22 오답 → 정확 (네 수치 모두 정답), e05 부분 → 정확 (고다층 MLB 포함)
- 부분 개선: e09 ICT 수출 751.5억은 맞췄으나, 함께 넘어간 '수입' 청크의 반도체 126.2억을 수출로 잘못 씀
- 나빠진 문항 없음 (판정 기준). 단, e01 이 내용은 같지만 "확인할 수 없습니다"로 시작하는 거절 형식으로 바뀜 → 생성 단계 문제
- 해결 안 됨: e14, e26, e33 — 의미 검색 순위로는 답 청크가 올라오지 않음 → 키워드 검색(하이브리드)이 필요

**결정**: 나빠진 문항 없이 정확 +2, 정답 문서 인용률 +0.118 → 기본값을 3으로 변경 (`rag/chain.CHUNKS_PER_DOC`). 비용은 컨텍스트 약 1.6배.

### 4. 실험 2 — 1차 자료 최소 보장 (`balance1`)

**가설**: 뉴스가 청크의 93.5%라 1차 자료(공시·보도자료·보고서)가 상위 6개에서 밀린다. 1차 자료를 따로 검색해
최소 N개를 보장하면 묻힌 정답이 올라온다. 단, 1위 문서보다 유사도가 많이 낮은 1차 자료는 넣지 않는다(격차 제한).

**격차 기준의 근거**: 대상 문항의 정답 1차 자료는 1위 대비 유사도 격차가 0.04~0.08, 뉴스가 정답인 e24·e29의 1차 자료는 0.17~0.24.

**검색 단계 비교** (`eval/exp_balance.py`, 문서 6개 기준, API 호출 없음)

| 변형 | Hit@6 | 대상 8문항 회복 | 1차 자료 평균 | 잃은 문항 |
|---|---|---|---|---|
| base | 0.824 | 3 | 1.5 | — |
| 최소 1 · 격차 0.06 | 0.882 | 5 | 1.68 | 0 |
| 최소 1 · 격차 0.08 | 0.941 | 7 | 1.73 | 0 |
| **최소 1 · 격차 0.10** | **0.971** | **7** | **1.77** | **0** |
| 최소 2 · 격차 0.10 | 0.971 | 7 | 2.2 | 0 |
| 고정 3+3 | 0.971 | 7 | 3.0 | 0 |

검색 성적이 같으면 뉴스를 가장 적게 빼는 '최소 1 · 격차 0.10'을 선택했다. Hit@1·Hit@3은 모든 변형에서 같다
(추가된 1차 자료는 유사도가 낮아 6개 중 아래쪽에 놓임).

**답변 결과** (chunks3 위에 1차 자료 보장만 추가 — 변수 하나)

| 지표 | baseline | chunks3 | balance1 |
|---|---|---|---|
| 정확 / 부분 / 오답 | 17 / 8 / 9 | 19 / 7 / 8 | **20 / 8 / 6** |
| 거절 정확도 | 6/6 | 6/6 | 6/6 |
| 과잉 거절 | 4 | 5 | 4 |
| 정답 문서 검색률 | 0.824 | 0.824 | **0.971** |
| 정답 문서 인용률 | 0.529 | 0.647 | 0.647 |
| 출처 정확성 (정확 / 오류) | 24 / 3 | 26 / 3 | **28 / 2** |
| 평균 응답 시간 | 2.85초 | 3.01초 | 3.47초 |

- 나빠진 문항 없음
- 한계: e16·e23 은 정답 DART 가 6위로 들어왔지만 모델이 쓰지 않거나 일부만 씀 → 검색이 아니라 생성 문제로 바뀜
- 관찰: 출처가 같은 15문항도 답변 문장이 달라졌다. temperature 0 이어도 OpenAI 응답은 실행마다 조금씩 달라질 수 있다
  → 1~2문항 차이는 오차 범위일 수 있으므로, 판정은 내용(정답 요소)이 바뀐 경우만 반영했다.

### 6. 실험 3 — 프롬프트 v2 (`prompt2`)

**가설**: balance1 에 남은 생성 실패(부분 답변을 거절 형식으로 시작, 상대 날짜 오해석, 뒤 순위 1차 자료 미사용,
의견 기사를 사실처럼 서술)는 프롬프트 규칙을 판단 순서와 예시로 바꾸면 줄어든다.
검색 결과는 balance1 과 완전히 같다(출처 달라진 문항 0) → 프롬프트만 바뀐 비교.

**바꾼 규칙** (`rag/prompts.SYSTEM_PROMPT_V2`, 예시는 평가 문항과 겹치지 않는 가상 회사·수치)
- 규칙 2: 질문 항목별 판단, 하나라도 근거가 있으면 거절 문장 금지 + 좋은 예/나쁜 예
- 규칙 5: 목록 뒤쪽 1차 자료도 확인, 의견 기사는 "주장/평가"로 서술
- 규칙 7: 수출/수입 등 비슷한 수치 구분
- 규칙 8: 보도일 기준 상대 날짜 변환 예시 2개

**결과**

| 지표 | balance1 (v1) | prompt2 (v2) |
|---|---|---|
| 정확 / 부분 / 오답 | 20 / 8 / 6 | 20 / **9 / 5** |
| 과잉 거절 | 4 | **0** |
| 거절 정확도 | 6/6 | 6/6 |
| 출처 정확 / 오류 | 28 / 2 | **25 / 4** |
| 정답 문서 인용률 | 0.647 | 0.529 |

- 개선: 과잉 거절 4 → 0. e01·e07 은 거절 문장 없이 답하고 빠진 부분을 ※로 표시. e25 오답 → 부분. e21 의견 기사를 "비판도 존재한다"로 구분
- 악화: 거절이 막히자 근거가 약한 답을 만들어 냄
  - e16: 뉴스 내용을 "2025년 사업보고서에서 설명"한다고 서술 (질문이 지정한 출처를 사칭) → 출처 오류
  - e07: 원문 "기존 최고였던 2022년(약 44조원)"을 "2023년"으로 씀
  - e25: 원문 "내년 예산 3574억"(2025년 보도 → 2026년)을 "2025년"으로 씀
- 상대 날짜 예시를 넣었는데도 날짜 오류가 오히려 2건 늘었다 → **프롬프트 문장만으로는 날짜 해석을 고치기 어렵다**
- 해결 안 됨: e16·e23 의 뒤 순위 DART 미사용, e09 수출/수입 혼동

**판단**: 정답 수는 같고(20), 형식 문제는 해결했지만 출처 오류가 2 → 4로 늘었다. 이 챗봇의 목적(근거 문서로 연결)에서는
출처 사칭이 과잉 거절보다 더 나쁘므로 v2 를 그대로 채택하지 않는다. 기본값은 v1 유지.

**다음 (v3 후보)**
- 날짜: 문장 지시 대신 **컨텍스트 머리줄에 기준 연도를 계산해 적는다** (예: `보도일 2025-01-23 → 이 문서의 '올해'=2025년, '지난해'=2024년, '내년'=2026년`).
  모델이 계산하지 않아도 되게 코드로 해결
- 출처 지정 질문: "질문이 사업보고서·보고서 등 출처를 지정하면 그 종류의 문서만 근거로 쓰고, 없으면 그 항목은 확인되지 않음으로 쓴다" 규칙 추가

### 7. 실험 4 — 프롬프트 v3 (`prompt3`)

**변경** (v2 기준, 검색 조건 동일)

**결과**

**결정**: 챗봇 기본 프롬프트를 v3 로 변경 (`rag/prompts.PROMPT_VERSION = "v3"`, 사용자 승인).
수치 차이는 변동 범위 안이고, 사용자가 화면에서 체감하는 거절 형식·출처 정직성에서 v3 가 낫다.

**문제**: 정답 문서는 찾았는데 답이 든 청크(표·요약)가 의미 검색 상위 50위 밖이라 모델에 전달되지 않는 문항 (e09 e14 e26 e33).

#### 최종 실행(kwchunk1) 전체 재채점

최종 실행은 이전 실행에서 달라진 문항만 고치지 않고 **40문항 답변 전문을 처음부터 다시 검토**했다 (`eval/grades_kwchunk1.json`).
- 답변의 숫자(연도 제외)를 모델에 실제로 전달된 문맥과 자동 대조 → **문맥에 없는 숫자 0건** (숫자를 지어낸 사례 없음)
- 남은 오류는 모두 '있는 숫자를 엉뚱한 연도·대상에 붙인' 유형:
  e07(2022년 → 2023년), e25(내년 예산 → 2025년), e34(중소기업 수출 → 반도체 수출 전체), e23(올해 → 2023년), e16(뉴스 → 사업보고서 사칭)
- ※ 출처 오류가 3 → 5 로 늘어난 것은 재검토에서 e25·e34 를 새로 잡아낸 영향이 크다. 중간 실험들은 변경 문항 위주로 채점해
  같은 유형을 놓쳤을 수 있으므로, 출처 오류 수의 실험 간 비교는 참고용으로만 본다.
- 채점자: Claude (채점 기준 1절 적용) → **사용자 검토 완료** (2026-11-09, 40문항 판정·출처 판정 전부 동의).
